# Development Journal

Development entries are recorded as Markdown files using the date:

```text
YYYY-MM-DD.md
```

Each entry records the goal, completed work, problems or decisions, verification
and next step.

Kanban snapshots use one date-first filename rule so they sort chronologically:

```text
YYYY-MM-DD-weekNN-day-kanban.html
```

The live board keeps the stable filename `project-weekly-kanban-board.html`. A
snapshot made again on the same day replaces that day's existing snapshot.

## Publication-aware daily closeout

BookLoop's final direction is an open-source book that teaches readers how to
develop an application service. It is not primarily a plan to operate BookLoop
as a commercial service.

Every daily journal should preserve a short publication trace without expanding
the current Deliverable scope:

- **Chapter candidate:** where this work may fit in the future book
- **Reader outcome:** what the reader can build or verify
- **Decision or failure:** why the implementation changed
- **Reusable evidence:** command, test, screen, diagram, snapshot, or commit
- **Privacy and cleanup:** material that must not enter the published source
- **Provenance:** whether code, text, images, and diagrams are original or reused

Every weekly closeout should identify one verified `chapter-complete` candidate,
its reproducible verification steps, and the most useful journal or presentation
evidence. Reused material should include its source and license candidate.
Manuscript writing begins only after the Web1 Final closeout; a verified HTML web
book is produced before the Kindle edition.
