01 · Teacher feedback → final UX

The normal request flow comes before the exceptional one.

Give the user the context needed to understand the exchange before taking action.

📌 Request status

✉️ Contact Mina

Keep the normal approved-contact action before the exceptional Report action.

🚩 Report this exchange

Keep the Report form closed by default and reveal it only through a small button.

04 · Project defense

Two answers explain the development journey.

Challenge

Connecting request status, approval, Contact and Report into one readable permission-aware flow without turning the product into a chat or moderation system.

Surprise

Edit/Delete initially looked disconnected during a slow presentation, but the live deletion demonstration showed that the database behavior was working.

Presentation rule

No separate PPT is required. Speak with the confidence of proposing the product to a real client and let the running system carry the proof.

The strongest defense is a short explanation followed by observable behavior: click it, see the result, then explain the boundary.
