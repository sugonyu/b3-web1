Folder boundary

FolderResponsibility
architecture/기술 구조, 관계와 결정 이유
design-system/시각 규칙, UI components와 states
backend/실제 Flask, SQLAlchemy와 JSON API
frontend-*실제 browser client 구현
docs/planning/일정, handoff, 결정과 다음 행동

Architecture evidence는 코드를 대신하지 않는다. 현재 구현과 비교해 차이가 발견될 때 이유를 기록하고 다음 버전으로 업데이트한다.

Shared naming convention

Design System과 Architecture 버전 폴더는 같은 형식을 사용한다.

vMAJOR.MINOR-dNN-topic[-lang]

각 버전은 기본적으로 README.md와 index.html을 가지며, 별도 스타일시트가 필요할 때만 style.css를 추가한다.

Agile architecture lifecycle

D1 v1.0  Korean architecture baseline
→ D1 v1.1  English translation of the same evidence
→ D2 v2.x  authentication + database workflow
→ D3 v3.x  React–Flask data flow
→ D4 v4.x  testing + errors + deployment structure
→ Final v5.x  stable architecture matching the current app

각 Deliverable에서 별도 architecture 발표가 없어도 실제 코드가 변하면 architecture evidence도 계속 iteration한다.
