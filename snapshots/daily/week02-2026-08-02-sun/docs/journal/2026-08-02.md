I selected the smallest Deliverable 2 vertical slice as one BorrowRequest from
creation to retrieval:

```text
POST /api/listings/<listing_id>/requests
→ GET /api/requests/<request_id>
```

The POST route already creates and persists a pending request. The missing piece
is a GET route that reads the same request ID. The read-authorization boundary
must be decided before that endpoint is treated as complete.

## Decisions and Remaining Risk

The final frontend direction remains React. Python/Jinja is a staged Deliverable 2
verification interface, not a replacement for React. Jinja routes and JSON API
routes must share the same service, validation, authorization, model, and database
logic so the frontend can change without rewriting the backend.

The BorrowRequest read boundary now uses Flask-Login's session `current_user`.
The borrower who created the request and the owner of the related listing are
allowed; unrelated users are rejected, and private contact data is not returned.

The remaining authentication risk is the real login entry path. Tests can establish
an authenticated session, but register, login, logout, password verification, and
browser-session behavior are not implemented yet. The Deliverable 2 authentication
item therefore remains incomplete.
