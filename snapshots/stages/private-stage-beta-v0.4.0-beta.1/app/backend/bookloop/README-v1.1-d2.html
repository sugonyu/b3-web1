1.1 · create_app() 설정과 모듈 조립

전체 지도를 읽기 전에 bookloop/__init__.py의 application factory를 먼저 이해합니다. 각 파일은 자기 역할을 정의하고, create_app()이 설정·extension·Blueprint·개발 명령을 하나의 Flask 앱으로 조립합니다.

🐍 HTTP Server · backend/run.py → create_app() → 설정 + extension → Blueprint 등록 → ⬛ CLI 등록

1 · 설정 준비

create_app(test_config=None)이 Flask 인스턴스를 만들고 환경변수 또는 테스트 설정을 적용합니다.

database URI · secret key · DEBUG · CORS 경계

2 · Flask extension 연결

db.init_app(app), Flask-Login, CORS가 앱에 연결됩니다.

extension 객체는 기능을 제공하고, factory는 실제 앱에 붙입니다.

3 · Blueprint 등록

api.py, clients/와 DB Inspector가 각자의 route를 정의하고 factory가 등록합니다.

Blueprint 정의 ≠ 서버 실행 · URL 책임을 모듈별로 분리

4 · 개발 명령 등록

⬛ backend/bl_cli.py는 별도의 application factory를 만들지 않습니다. bookloop/__init__.py의 같은 create_app()을 호출합니다.

run.py는 app.run()으로 HTTP 서버를 시작하고, BL-CLI는 앱 context 안에서 db.create_all()과 seed/reset을 실행합니다.

핵심 구분: client_jinja.py나 api.py가 앱을 따로 실행하는 것이 아닙니다. 이 파일들은 Blueprint와 route를 정의하고, create_app()이 모두를 조립한 뒤 run.py가 서버를 시작합니다.

웹과 터미널: run.py와 bl_cli.py는 서로 다른 실행 입구이지만 create_app(), SQLAlchemy model, BorrowRequest service를 공유합니다. 즉 different entry points · same application factory입니다.

2 · BL-CLI 관리 도구

웹 서버 진입점과 로컬 개발·데모 관리 진입점을 분리합니다.

Fig 2-1 · BL-CLI 터미널 실행 흐름

⬛ backend/bl_cli.py → devtools/bl_cli/ → commands.py ＋ seed/ → SQLAlchemy · SQLite

실행 입구

python3 bl_cli.py는 명령 목록과 사용 예시를 보여줍니다.

python3 bl_cli.py seed-demo
사용자·책·초기 데모 데이터를 준비합니다.

python3 bl_cli.py reset-demo-requests
The Odyssey의 BorrowRequest만 초기화합니다.

명령 조립

bookloop/devtools/bl_cli/commands.py가 Click command와 Flask application context를 연결합니다.

seed-demo는 전체 시작 데이터, reset-demo-requests는 요청 테스트 재시작용입니다.

Seed 기능

bookloop/devtools/bl_cli/seed/commands.py가 demo user, listing과 선택적 request reset을 담당합니다.

도구 경계: DB Inspector는 브라우저용 read-only 도구로 BL-CLI의 형제인 devtools/db_inspector/에 유지합니다.

3 · W2-07 공통 BorrowRequest Service

API와 다음 Jinja 제품 화면이 같은 업무 규칙으로 합류합니다.

공유 지점: api.py는 React·Vanilla 같은 HTTP client가 사용하는 JSON 진입점이고, Jinja와 React가 실제로 공유하는 것은 services/borrow_requests.py의 validation·authorization·transaction 규칙입니다.

검수 링크: 🐍🟨 Flask Vanilla :5000 ↗ · 🟨 Independent JS Vanilla :8080 ↗

Route

HTTP 입력을 읽고 service 오류를 status code로 바꾸며 JSON 또는 HTML 응답을 선택합니다.

Service

create_borrow_request()와 get_authorized_borrow_request()가 공통 업무 규칙을 실행합니다.

Model

User·BookListing·BorrowRequest 관계를 정의하고 유효한 데이터를 SQLite에 영속화합니다.
