# Development Journal — 2026-08-03 (Monday)

Daily focus: Create a reproducible and safe starting state for the browser demo.

## Goal

The first Monday checkpoint was to prepare Tony, Mina, Alex, and one available
Almond listing without creating the BorrowRequest that must be demonstrated in
the browser.

## What I Faced and Attempted

The seed needed to be easy to rerun without deleting existing data or exposing a
demo password in source control. I separated it from the read-only database
inspector and implemented it as an explicit Flask CLI command under the developer
tools package.

The command reads `BOOKLOOP_DEMO_PASSWORD` from the local environment, stores only
its hash, creates missing demo records, and leaves existing matching records in
place. It intentionally does not create a BorrowRequest.

## What I Achieved

- Added the `seed-demo` Flask CLI command.
- Created Tony as borrower, Mina as Almond owner, and Alex as unrelated test user.
- Created Mina's available Almond listing.
- Kept BorrowRequest at zero so the live form remains the proof of creation.
- Documented the command and local password boundary.
- Verified that a second run creates no duplicate users or listing.
