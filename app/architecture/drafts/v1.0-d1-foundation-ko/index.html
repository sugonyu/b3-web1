Model relationships

User → BookListing

1 user → many listings

한 회원은 여러 한국책을 공유 목록에 등록할 수 있다.

User → BorrowRequest

1 borrower → many requests

한 회원은 여러 책에 대여 요청을 만들 수 있다.

BookListing → BorrowRequest

1 listing → many requests

한 책 등록은 시간에 따라 여러 대여 요청을 받을 수 있다.

User (owner)       1 ─────────── many BookListing
User (borrower)    1 ─────────── many BorrowRequest
BookListing        1 ─────────── many BorrowRequest

Core model fields

User

FieldRole
id사용자를 구분하는 primary key
username공개 화면에서 사용할 고유 이름

BookListing

FieldRole

title책 제목
author저자
availability현재 대여 요청 가능 여부
owner_id소유자인 User를 가리키는 foreign key

BorrowRequest

FieldRole
id대여 요청을 구분하는 primary key
statuspending, approved, rejected, returned
listing_id요청한 BookListing foreign key
borrower_id요청을 만든 User foreign key

Why BorrowRequest?

User + BookListing만 있으면 책을 보고 외부에서 연락하는 디렉터리에 머문다. BorrowRequest는 요청, 승인·거절과 반납 완료를 앱 안에 기록하고, 완료 거래는 이후 optional trust rating의 근거가 된다.

Privacy boundary

  • 공개: username, general_area, 책 정보와 availability
  • 비공개: email, password_hash, 정확한 주소와 전화번호
  • 연락 정보 공개 방식은 인증·승인 workflow 구현 때 다시 결정한다.

Short presentation explanation

BookLoop uses three related models. A user can own many book listings and can create many borrow requests. Each borrow request connects one borrower to one listing and records the borrowing status. The current Flask API and SQLAlchemy models are separated from the browser clients, so the future React client can consume the same JSON API without changing the database model.
