## What I Faced and Attempted

The seed needed to be easy to rerun without deleting existing data or exposing a
demo password in source control. I separated it from the read-only database
inspector and implemented it as an explicit Flask CLI command under the developer
tools package.

The command reads `BOOKLOOP_DEMO_PASSWORD` from the local environment, stores only
its hash, creates missing demo records, and leaves existing matching records in
place. It intentionally does not create a BorrowRequest.

The product screen also needed to avoid creating a second set of business rules.
The Jinja routes therefore call the same BorrowRequest service already used by
the JSON API. The browser receives HTML and redirects while the API retains JSON
responses, but duplicate prevention, owner checks, authorization, and database
transactions remain shared.
